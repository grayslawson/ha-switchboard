Status: **open / partial**. The source harness and deterministic Core-local

and one-shot replay. The preserved local fixture has a bounded opt-in live
probe for same-conversation continuation, cancellation, and replay.

  — expected to pass with the live follow-up probe skipped unless
  `HA_SWITCHBOARD_RUN_FOLLOW_UP=1` is explicitly set.
- `HA_SWITCHBOARD_RUN_FOLLOW_UP=1 python3 -m pytest -q tests/test_e2e_harness.py -k live_follow_up_fixture`
  — passed against the preserved disposable Core/Supervisor fixture after the
  harness was corrected to execute inside the nested Core container. The
  bounded probe proved same-conversation continuation, cancellation, and
  one-shot replay; it reported the second-user and natural-TTL cases as
  unavailable with safe reasons.

The live command was read-only with respect to the Supervisor/Core volume and
retained only sanitized JSON in the test assertion. No token, user reference,
entity reference, utterance, provider body, or conversation identifier is
recorded here.

## Remaining gates

- Different-user live proof requires a second existing Home Assistant user
  token supplied through a safe, in-memory test boundary. The current fixture
  helper intentionally mints only its existing owner token and does not mutate
  the auth store; the second-user case therefore remains `unavailable`.
- Natural TTL live proof requires waiting for the real Core continuation TTL
  after the first Assist turn. The current helper has no safe clock injection
  or bounded TTL override, and this task does not authorize changing Core,
  restarting the environment, or waiting an uncontrolled interval; the
  natural-expiry case therefore remains `unavailable`.

T059 cannot be checked honestly until both live gates produce sanitized
`proved` results. Deterministic expiry and cross-user tests are not substitutes
for those live claims.
